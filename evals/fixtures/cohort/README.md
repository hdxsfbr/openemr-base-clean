# AgentForge Synthetic Cohort (`af-cohort-v1`)

A deterministic set of **fictional** patients loaded into a **local development**
OpenEMR database. It exists for two reasons:

1. **Audit:** measure latency, payload size, and retrieval correctness at
   realistic volume. The bundled demo data (3 patients, 0 labs, 0 notes) cannot
   (`docs/audit/data-quality.md` DQ-CRITICAL-001).
2. **Evals:** give every boundary, invariant, and failure-mode case in
   `evals/README.md` a stable patient to run against.

Every name, date, value, and note is synthetic. Never load real patient data
here.

## What synthetic data can and cannot prove

The defects below are **planted**. They reproduce row shapes that OpenEMR's
schema and code demonstrably allow, as observed in the audit. A passing eval
shows the co-pilot handles the defect. It does **not** show how often the
defect occurs in real clinics. Report fixture-based results as synthetic, and
keep them separate from audit observations.

## Load

Prerequisites: the local `development-easy` stack with the demo database
loaded (`SETUP.md`), and the audit test users `audit-physician`, `audit-nurse`
(see `docs/audit/evidence/security/live-cross-patient-test.md`), plus the
bundled `physician` user. `seed_users.php` in this directory creates the
users the evals expect (`physician`, `audit-physician`, `audit-nurse`,
`audit-frontdesk`; idempotent, existing usernames skipped) and is what the
deployment's `demo-seed` job runs before `seed_cohort.php`.

```bash
docker exec development-easy-openemr-1 sh -c 'cd /var/www/localhost/htdocs/openemr && su -s /bin/sh apache -c "php evals/fixtures/cohort/seed_cohort.php --confirm-dev-data"'
```

Options:

- `--anchor=YYYY-MM-DD` sets "today" for all relative dates and appointments.
  It defaults to the current date. Use a fixed anchor for reproducible eval
  runs, and record it with results. The deployment's `demo-seed` job
  (`infra/digitalocean/runtime/compose.yaml`) passes `--anchor=${DEMO_ANCHOR:-2026-09-15}`.
- `--reset-only` removes the cohort without reloading.

The script prints a JSON manifest (pids, scenarios, required behaviors,
volumes, post-load checks) and exits non-zero if any check fails.

## Guarantees and side effects

| Property | Behavior |
| --- | --- |
| Determinism | Same patients, row ids, values, and relative dates on every load for a given anchor. Heavy-patient variation uses a fixed RNG seed. UUIDs are generated by OpenEMR and differ between loads. |
| Idempotence | Deletes everything in the cohort ranges, then reloads, inside one transaction. Refuses if the pid range contains patients not prefixed `AF-`. |
| Ranges | Patients: pid `900001–900099`, `pubpid` `AF-*`. Clinical rows: ids `9000000–9099999` (`ID_MIN`/`ID_MAX` in `seed_cohort.php`). Lab provider: `ppid 900001`. |
| Auto-increment | After loading, the affected tables' `AUTO_INCREMENT` is raised to `9100000`, so application-created rows never fall inside the cohort range. New app patients will receive pids above `900099`. |
| UUIDs | Assigned at insert time through `UuidRegistry::createUuid()` and removed from `uuid_registry` on reset. The seed does not use the table-wide backfill: its `UPDATE … SET uuid` fires `ON UPDATE CURRENT_TIMESTAMP` columns (`lists.modifydate`, `*.last_updated`, `form_encounter.last_update`) and would erase planted modification dates. |
| Timestamps | `lists.modifydate`, `last_updated`, and similar columns keep their planted values. Any later application UPDATE to a cohort row will overwrite them. Reload before evals that depend on them (AF-DQ-D). |
| Audit log | Inserts run with statement logging disabled, so the seed does not flood `log`. |
| Web access | The script returns 404 when requested over HTTP. Do not ship `evals/` in a deployed image (SEC-HIGH-500). On the deployment it runs from a read-only bind mount outside the web root via the one-shot `demo-seed` job, with `OPENEMR_ROOT` pointing at the application tree (`AUDIT.md` §7.2, `docs/deployment/digitalocean.md`). |
| Post-load checks | Patient count; exactly 1 orphan form and 1 orphan lab result (intended, DQ-P); 0 forms attached to another patient's encounter; appointment count for `audit-physician` today; 0 cohort rows missing UUIDs. |
